# The Starry Palace — Cloudflare Pages preview (no switch of the live Render site)

This is a **parallel preview deployment**, not a DNS migration. Keep `https://the-starry-palace.onrender.com` working until the alternative has been tested. No new application database or Supabase migration is required.

## Why this exists

The Render static site reached its pipeline-minute allowance in October 2026. GitHub tests and production-build checks were still passing, but Render declined subsequent builds before running them. Cloudflare Pages can build the same Vite/React repo in parallel.

The production build is host-aware: `CF_PAGES=1` (set automatically on Cloudflare Pages) skips `dist/404.html` so Cloudflare's native SPA fallback handles links such as `/reading`, `/writing`, `/account`, `/auth/callback` and individual story/chapter routes. Render still gets a copy of `index.html` as `dist/404.html`. No rewrite of routes or data is required.

## One-time dashboard setup

1. Sign in to **the intended Cloudflare account** at https://dash.cloudflare.com/ . Do not edit the district office's website or DNS zone.
2. Go to **Workers & Pages → Create application → Pages → Import an existing Git repository**. Authorize Cloudflare's GitHub app for **only** `annalisegeorge1/The-Starry-Palace` if that is sufficient.
3. Create a separate Pages project, e.g. `the-starry-palace-preview` if the name is available. Keep its default `*.pages.dev` address. **Do not connect any custom domain or update DNS.**
4. Set **Production branch:** `main`; **Framework preset:** Vite (or React/Vite); **Root directory:** repository root; **Build command:** `npm run build`; **Output directory:** `dist`. Use Node.js 22 or set `NODE_VERSION=22` if the selected build image differs. The Pages Git integration will install the dependencies.
5. Under **Settings → Environment variables**, add `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for both production and preview environments. Obtain their browser-safe values from the project dashboard or the existing `.env.example`; the values must match the same Supabase project used by Render. **Do not put `sb_secret_` keys, service-role keys, database passwords, API bearer tokens or Cloudflare API tokens in `VITE_` variables.** Browser `VITE_` variables become public JavaScript.
6. Deploy to the autogenerated `https://<your-project>.pages.dev` preview host. Do not assume a project URL until Cloudflare supplies the actual address.
7. In the existing **Supabase → Authentication → URL Configuration**, keep the current primary **Site URL** unchanged. Add the **exact new preview origin** and `/auth/callback` to **Redirect URLs** (for example, `https://<your-project>.pages.dev/auth/callback`; add `https://<your-project>.pages.dev/**` only if actual login/reset flows need deeper return paths). Use tightly scoped exact URLs wherever practical, not an unrestricted `https://**.pages.dev/**` wildcard.
8. Test from a private or separate browser profile and a test member account. Test the login callback, password reset email, logout, reading, saving, the writing pad, chapter save/reopen, imagery, mobile nav, Palace profile, and direct refresh of `/writing` and `/reading`. Never submit a test story to production unless intentionally testing it.

## Important data and release precautions

- The preview points to **the same Supabase database** unless you explicitly provision separate test infrastructure. Changes created by test accounts, including posts, votes, awards, uploads and published works, may be real. Test cautiously.
- Moving from `onrender.com` to `pages.dev` changes the **browser origin**, so browser-local drafts/preferences/sessions do **not** automatically transfer. Save drafts to the Palace and download a text backup before testing; sign in again on the preview domain. Do not promise that unsaved device drafts migrate automatically.
- Both Cloudflare and Render can host static front-end files; Supabase still handles the database, accounts, storage and authorization. Verify **RLS** and storage permissions independently.
- Do not replace the production Site URL, migrate domains, rotate or publish secrets, alter DNS, or shut down Render as part of creating this preview.
- Keep GitHub Action **Palace build checks** passing before merging changes. Render's exhausted allowance requires replenishment or its normal reset; adding Cloudflare does not restore Render's quota.
- If Cloudflare Pages displays a working home page but login fails, inspect the two build variables and Supabase Auth redirect allowlist before changing application code. If deep links fail, confirm the Cloudflare build output has **no root `404.html`** and `CF_PAGES=1` was injected.

This preview does **not** change the existing live host. If it fails, stop testing its `pages.dev` URL, leave Render live, and inspect the Cloudflare build/deployment logs. Do not remove or rewrite the existing Supabase users or stories.
